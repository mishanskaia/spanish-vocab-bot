# CLAUDE.md — Руководство для нового ИИ-разработчика

Этот файл написан так, чтобы ИИ без какого-либо предыдущего контекста мог продолжить разработку.
Читай внимательно: здесь объясняется не только ЧТО сделано, но и ПОЧЕМУ.

---

## Что это за проект

Telegram-бот для изучения испанского языка с нуля. Пользователь — русскоязычный, уровень A1-A2.
Бот хранит словарный запас и повторяет слова по кривой интервальных повторений.

Это самостоятельный проект. Существует также похожий английский бот (`../vocab_bot/`) —
он послужил архитектурной основой, но это разные боты с разными БД и разными токенами.

---

## Как запустить локально

```bash
pip install -r requirements.txt
# создай .env на основе .env.example, заполни токены
python bot.py
```

Переменные окружения:
```
TELEGRAM_BOT_TOKEN=...      # токен от BotFather
ANTHROPIC_API_KEY=...       # ключ Anthropic (тот же что у английского бота — они независимы)
DB_PATH=/data/spanish_vocab_bot.db  # на Railway; локально можно опустить (будет spanish_vocab_bot.db)
API_KEY=...                 # секрет для чтения через API (см. раздел «API» ниже); не задан — чтение отключено
API_WRITE_KEY=...           # секрет для добавления слов через API; не задан — запись отключена
```

## Деплой

Railway.app, сервис `spanish-vocab-bot` внутри проекта `vocab-bot` (там же живёт английский бот).
Persistent Volume примонтирован на `/data` — без него БД сбрасывается при каждом рестарте.
Деплой автоматический при пуше в ветку `main` на GitHub: `mishanskaia/spanish-vocab-bot`.

## API

Отдельный внешний сайт может читать и добавлять слова пользователя через HTTP — например,
дашборд или форма для быстрого добавления слов, которые потом учатся в Telegram как обычно.
Сервер поднимается прямо внутри `bot.py`, в том же процессе и контейнере, что и сам Telegram-бот
(через `aiohttp`, запускается в `post_init` рядом с polling'ом — не отдельный Railway-сервис).
Запись безопасна из того же процесса — конфликтов параллельной записи, как между разными
процессами/сервисами, тут нет.

```
GET  /words?user_id=<telegram_user_id>&key=<API_KEY>
POST /words   {"user_id": <telegram_user_id>, "word": "aburrido", "key": "<API_WRITE_KEY>"}
GET  /health  # без авторизации, просто проверка что процесс жив
```

- `GET /words` — читает список слов. Без `API_KEY` в переменных окружения — всегда отвечает 401
  (сознательно).
- `POST /words` — принимает только само слово/фразу; перевод, примеры, спряжение и т.п. генерирует
  Claude через `ai_helper.explain_word()` — точно так же, как при обычном сообщении боту напрямую.
  Сохраняет через `db.add_word()`, так что дедуп по фразе (без учёта регистра) работает так же, как
  и в Telegram — повторная отправка того же слова не создаёт дубль, просто вернёт существующее.
  Без `API_WRITE_KEY` в переменных окружения — всегда отвечает 401.
- **Читающий и пишущий ключ — разные** (`API_KEY` и `API_WRITE_KEY`), сознательно: read-ключ можно
  отдать куда-то для просмотра (например, публичному дашборду), не давая тем самым право писать.
- Если понадобится доступ с другого процесса/сервиса (не из этого же контейнера) — вот тогда стоит
  мигрировать на Postgres, SQLite не для параллельной записи из разных процессов.
- Чтобы сайт был доступен снаружи — нужно включить публичный домен для сервиса в Railway
  (Settings → Networking → Generate Domain, порт 8080). Без этого сервис слушает порт, но наружу
  не торчит.
- CORS открыт (`Access-Control-Allow-Origin: *`) — авторизация целиком на `key`, так что это ок для
  персональных данных за секретным ключом, но не делай так для чего-то чувствительнее.

## Архитектура: три файла

### `bot.py` — всё что связано с Telegram
Хендлеры команд, кнопок, сообщений. Логика отображения карточек повторения.
Состояние очередей хранится в `context.user_data` — **эфемерно**, теряется при рестарте бота.

### `db.py` — вся работа с SQLite
Схема таблицы, CRUD, логика интервалов, определение окна суток, пулы overdue/scheduled.
**Не держи бизнес-логику интервалов в bot.py** — всё в db.py.

### `ai_helper.py` — два промпта к Claude Sonnet 4.6
- `explain_word(word)` — объяснить одно слово
- `find_frequent_words(existing_words, count)` — подобрать N новых слов

Claude отвечает только JSON. Парсинг в `_ask_claude()` — стрипает markdown-обёртку если есть.

## Схема БД (таблица `words`)

```sql
id, user_id, phrase, meaning, part_of_speech, cefr_level,
examples (JSON-массив строк, 3 штуки),
collocations (JSON-массив строк "фраза — перевод", 2-4 штуки или []),
conjugation (строка или NULL, только для глаголов),
gerund (строка герундия или NULL, только для глаголов),
added_date, interval_stage (0–6), next_review_date,
correct_streak, status, times_reviewed, success_rate, last_reviewed,
pool ('scheduled'|'overdue'),
added_window ('morning'|'evening')
```

**Важные инварианты:**
- Существительные в `phrase` — всегда с артиклем: `la casa`, `el coche`. Это требование к промпту.
- Глаголы в `phrase` — инфинитив: `hablar`, `ser`. Спряжение отдельно в `conjugation`.
- `examples` — JSON-массив, хранится как TEXT. При чтении всегда `json.loads(row["examples"] or "[]")`.
  Каждая строка — `"испанское предложение — русский перевод"` в одной строке через " — " (см. промпт
  в `ai_helper.py`). Это load-bearing формат: карточки повторения парсят его через `_split_example()`
  в `bot.py`, чтобы показать русский перевод как контекст, когда не получилось сделать пропуск.
- `status = 'skipped'` — слово пропущено в /words. Не участвует в повторениях, но передаётся Claude чтобы не предлагал повторно.
- `pool = 'overdue'` — слово не было повторено в срок. Устанавливается в `detect_and_mark_overdue()`.

## Логика интервальных повторений

```python
INTERVALS = [1, 3, 7, 14, 30, 90]  # дней, 6 ступеней
```

**Первое повторение** — в тот же день или на следующий, зависит от окна суток (МСК):
- Утро (6–14): `next_review_date = сегодня`, `added_window = 'morning'`
- Вечер (14–23) или ночь: `next_review_date = завтра`, `added_window = 'evening'`

**Оценка при повторении** (`mark_review_result(word_id, grade)`), три градации:
- `'remember'` (🟢 Помню): `stage += 1`, дней = `INTERVALS[stage]`
- `'almost'` (🟡 Почти помню): `stage` не меняется, дней = `max(1, round(INTERVALS[stage] * 0.8))`
- `'hard'` (🔴 Сложно): `stage` не меняется, дней = `max(1, floor(INTERVALS[stage] * 0.6))`

`'almost'` добавлена 2026-09-02 как средняя градация между «вспомнил» и «не вспомнил» — раньше
self-grade был бинарным, и пограничные случаи (слово узнал, но не сразу/не уверенно) приходилось
искусственно относить к одной из двух крайностей. **Не путать со старым `'easy'`**: третий grade уже
был раньше — сидел НАД `'remember'` (ускоренный интервал `*1.3` для "слишком легко") и его убрали,
судя по всему потому что учащиеся склонны переоценивать лёгкость и разгонять интервал быстрее, чем
слово реально закрепилось. `'almost'` сидит НИЖЕ `'remember'`, между ним и `'hard'`, и намеренно НЕ
продвигает `stage` — только смягчает интервал по сравнению с `'hard'`. Если будешь трогать эту логику
ещё раз, не давай `'almost'` продвигать `stage` — это и есть грабли из старого `'easy'`.

Мнемоника (`_maybe_ask_mnemonic`) теперь предлагается при любом grade кроме `'remember'` — то есть и на
`'almost'`, и на `'hard'` (раньше — только на `'hard'`).

После stage 5 (последнего) → `status = 'mastered'`.

**Overdue:** если `next_review_date < сегодня` и `pool = 'scheduled'` → `pool = 'overdue'`, `stage -= 1`.
Вызывается в `detect_and_mark_overdue(user_id)` при старте каждой сессии /review.

## Пользовательский флоу

### Добавление слова
Пользователь пишет любой текст (не команду) → `handle_message()` → Claude → сохранить в БД.
**Нет команды /add** — это сознательное решение для простоты UX. Не добавляй /add без нужды.

### /words
Подбирает 5 новых слов через Claude. Передаёт список ВСЕХ слов пользователя (включая skipped)
чтобы Claude не повторялся. Слова показываются по одному с кнопками Сохранить/Пропустить.
Пропущенные сохраняются в БД со статусом `skipped`.

Было 10 слов — уменьшено до 5 из-за таймаута Claude (генерация 10 слов со спряжениями занимает >60 сек).

### /review
1. Очищает `context.user_data["review_shown"]` (set ID уже показанных в этой сессии)
2. Вызывает `detect_and_mark_overdue()`
3. Отправляет `RECALL_DISCLAIMER` один раз в начале сессии (напоминание, что ответ — в словарной форме)
4. Показывает overdue-слова первыми (с ⚠️), потом scheduled
5. Все карточки — активное воспоминание, self-graded (см. «Типы карточек» ниже)

### /all
Повторить все слова из базы в случайном порядке, без учёта расписания.
Использует отдельную очередь `context.user_data["all_queue"]`.
После grade — переходит к следующему в очереди, не перезапрашивает БД.

## Типы карточек при повторении

Раньше было два формата — recognition (перевод → вспомни слово) и fill-in-the-blank
multiple choice (пропуск в предложении + 3 кнопки-варианта). MC убрали: узнавание среди
готовых вариантов не задействует активное воспоминание так, как задействует свободное
воспроизведение (testing effect). Теперь один формат — активное воспоминание с контекстом,
всегда self-graded (кнопка «Показать ответ» → три кнопки оценки Помню 🟢 / Почти помню 🟡 / Сложно 🔴,
см. «Логика интервальных повторений» выше).
Ответ всегда показывается в словарной форме (`row["phrase"]`) — инфинитив для глаголов,
с артиклем для существительных — даже если в примере слово стоит в другой форме. Отсюда
`RECALL_DISCLAIMER`, который бот один раз показывает в начале сессии /review и /all.

Логика в `_build_recall_prompt()` (`bot.py`), три уровня по убыванию:

1. **Пропуск в предложении.** Берёт первый пример из `examples`, ищет испанскую часть слова
   (без артикля для существительных) в испанской половине примера (`_split_example()`),
   заменяет на `_____`. Показывает пропуск вместе с русским переводом предложения.
2. **Контекст без пропуска.** Если слово не нашлось в тексте (частая причина — глагол в
   примере стоит в спряжённой форме, а не в инфинитиве) — показывает русский перевод
   предложения как подсказку-контекст плюс явный вопрос "Как будет по-испански: {meaning}".
3. **Голый перевод.** Если у слова вообще нет примеров или строка не содержит `" — "` —
   fallback на самый простой формат: "Как будет по-испански: {meaning}".

Функция `_make_blank()` делает точный поиск подстроки, не морфологический — для глаголов
попадает в уровень 1 редко (только если в примере случайно тот же инфинитив), обычно
уходит на уровень 2. Это ожидаемо и нормально, а не баг.

## Уведомления и лимит на сессию

- **10:00 / 14:00 / 18:00 МСК** (07:00 / 11:00 / 15:00 UTC) — `morning_reminder()` / `midday_reminder()` /
  `evening_reminder()`, все три через общий `_run_reminder()`. Три сессии в день вместо одной —
  добавлено 2026-09-03: при большом бэклоге (сто и больше слов) одна сессия утром пугает и отбивает
  желание открывать бота вообще; исследование (spacing effect, Anki/SuperMemo best practices)
  подтверждает, что несколько сессий по 20-30 карточек лучше для запоминания, чем одна массированная.
- `SESSION_WORD_LIMIT = 30` — жёсткий лимит слов за одну сессию (не только новых — вообще всех
  показанных карточек). Считается по `len(review_shown)` в `_send_next_due()`. При достижении —
  сообщение "На эту сессию хватит" вместо карточки; остаток ждёт следующей сессии, каждая сессия
  (реминдер или ручной `/review`) сбрасывает `review_shown` и даёт свежие 30.
- Реминдер отправляется только если есть слова, не повторённые сегодня (`count_due_not_reviewed_today()`).
  Текст показывает `min(count, 30)` как «слов на эту сессию», и только если реальный бэклог больше —
  тихой строкой ниже «всего в очереди: N» — чтобы не пугать полным числом каждый раз.
- После уведомления сразу начинается сессия повторения.

## Статусы слов

| status | stage | Смысл |
|--------|-------|-------|
| collected | 0 | Добавлено, ещё ни разу не повторялось |
| learning | 1–2 | Активно учим |
| familiar | 3–4 | Знакомо |
| active | 5 | Уверенно |
| mastered | 6 | Выучено, не показывается в /review |
| skipped | — | Пропущено в /words, не участвует в повторениях |

## Известные проблемы и ограничения

1. **context.user_data эфемерно** — очереди /words и /all, а также `review_shown` теряются при рестарте бота на Railway. Пользователь должен начать заново. Для фикса нужно хранить состояние в БД.

2. **/words может быть медленным** — Claude генерирует 5 слов с примерами и спряжениями, занимает 15–30 сек. Бот показывает "Подбираю слова, подожди немного..." но второй индикатор прогресса нет.

3. **Пропуск в предложении часто не получается сделать** — если пример не содержит точного вхождения слова (другая форма глагола, множественное число существительного и т.д.), карточка падает на уровень 2 (контекст без пропуска) или 3 (голый перевод). Это ожидаемо, не баг — см. «Типы карточек».

4. **Overdue-пул не сбрасывается автоматически** — если пользователь не заходит несколько дней, слова накапливаются в overdue. При следующем /review все придут сразу. Это намеренно.

## Что планировалось но не сделано

- **Озвучка слов** — голосовое сообщение с произношением. Отложено до фазы immersion (требует TTS-сервис).
- **Фаза /topic** — подбор слов по теме (как в английском боте). Пока не реализовано.
- **Хранение состояния сессий в БД** — чтобы не терять очередь при рестарте.
